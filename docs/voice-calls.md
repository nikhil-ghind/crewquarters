# Realtime voice calls

The owner can place a phone call in which the other person talks with the local models, in
real time. The call runs through Twilio. Speech-to-text, the chat model, and text-to-speech
all run on the device.

| Step | Where | Model (default) |
| --- | --- | --- |
| Caller audio in: 8 kHz mu-law, 20 ms frames | Twilio Media Stream -> tunnel -> proxy callbacks site -> capability broker | |
| End of the caller's turn: energy voice-activity detection (700 ms of silence) | broker (`crewquarters_broker.voice_audio`) | |
| Transcript of the turn | gateway `POST /internal/v1/audio/transcriptions` | `local.asr.r2t2` (Confucius4-R2T2) |
| Reply, streamed token by token | gateway `POST /internal/v1/llm/chat` (stream) | `local.general.small` (Qwen2.5-7B) |
| Speech, streamed word by word as the reply arrives | gateway WebSocket `/internal/v1/audio/speech/stream` | `local.tts.voxtream` (VoXtream) |
| Assistant audio out: 24 kHz PCM -> 8 kHz mu-law | broker -> Twilio (`media`, then a `mark`) | |

If the caller talks over the assistant for 300 ms (`CQ_VOICE_BARGE_IN_MS`), the broker sends
Twilio a `clear` (drops the buffered audio) and cancels the reply. A call ends when the
caller hangs up, the owner presses **Hang up**, or after `CQ_VOICE_MAX_CALL_SECONDS`.

## Using it

1. Configure Twilio in **Connections -> Twilio** (account SID, auth token, caller number).
2. Set the allowed destinations and the public callback address (below), and start the
   callback tunnel: `sudo crewquarters tunnel up`.
3. Install the three models on the **Models** page. They load on demand; the first call
   after a cold start waits for them (about 90 s for R2T2, 150 s for Qwen, 30 s for VoXtream).
4. **Connections -> Twilio -> Talk to your crew**: enter an allowed number, pick a voice,
   optionally give instructions, confirm. The transcript updates live, with per-turn
   latency.

## Configuration

| Variable | Where | Purpose |
| --- | --- | --- |
| `CQ_TWILIO_CALLBACK_BASE_URL` | `/etc/crewquarters/crewquarters.env` | The tunnel's public `https://` origin. Twilio connects the media WebSocket to `wss://<this>/api/v1/callbacks/twilio/media/<id>`. Calls are refused if it is not https. |
| `CQ_TUNNEL_TOKEN` | `/etc/crewquarters/secrets.env` | The Cloudflare tunnel token (hostname pointed at `http://proxy:8081`); see [runbooks/proxy.md](runbooks/proxy.md). |
| `CQ_TWILIO_ALLOWED_NUMBERS` | `/etc/crewquarters/crewquarters.env` | JSON list of E.164 numbers the broker may call, for example `["+15551234567"]`. Trial accounts can call only numbers verified in the Twilio console. |
| `CQ_VOICE_CLIENT_TOKEN` | `secrets.env` (generated by the installer) | Lets the broker (and only the broker) use the gateway's audio routes and local chat for a call. |
| `CQ_VOICE_ASR_MODEL`, `CQ_VOICE_LLM_PROFILE`, `CQ_VOICE_TTS_MODEL` | `crewquarters.env` | The models a call uses (defaults above). |
| `CQ_VOICE_MAX_CALL_SECONDS` | `crewquarters.env` | Call length limit (default 300). |

## Security and privacy

- **Consent and disclosure.** Destinations are limited to `CQ_TWILIO_ALLOWED_NUMBERS`, the
  owner confirms every call in the UI, and Twilio speaks a fixed disclosure ("an automated
  call ... an AI assistant ... transcribed for its owner") before the conversation starts.
  Calling, recording, and privacy rules differ by jurisdiction: get legal review before real
  use.
- **Stream authentication.** Each call has an unguessable one-time token, passed to Twilio in
  the TwiML as a `<Parameter>` and checked in the stream's `start` message, and the
  WebSocket handshake must carry a valid `X-Twilio-Signature`. A stream URL can be used once.
- **Exposure.** The callback site (`infra/proxy/callbacks-site.conf`) adds only the
  `/api/v1/callbacks/twilio/media/` WebSocket route; the UI, `/api/v1/*` and `/internal/*`
  stay unreachable from the tunnel.
- **Credentials.** The broker calls the gateway with the service token plus
  `CQ_VOICE_CLIENT_TOKEN`. That credential can use local chat only for a `voice` holder
  (never an owner chat session, never a cloud model), and release only `voice:` leases.
- **Data.** Audio is never stored. The transcript lives in the broker's memory for the live
  view and is dropped an hour after the call; the audit log (`voice_call.started`,
  `voice_call.ended`) holds the masked number, duration, and turn count only. Gateway usage
  rows hold latency and outcome, no text.
- **Voices.** VoXtream clones the voice of a short sample. Only the two sample voices from
  the VoXtream repository are offered; there is no voice upload, so no one's voice can be
  used without consent.

## Leases and memory

A call holds one lease per model (`manual`, holder `voice:<call id>`), renewed on each use
and released when the call ends; if the broker dies, the leases expire after
`CQ_GATEWAY_VOICE_LEASE_TTL_SECONDS` (600). Speech-to-text and text-to-speech models are not
"generative", so they load beside the chat model; the memory checks still apply. Measured on
a GB10: R2T2 about 14 GiB, Qwen2.5-7B about 32 GiB, VoXtream about 5.4 GiB.

## Testing without a phone

`POST /internal/v1/voice/calls` with `"simulate": true` (service token) creates a session
without dialing and returns its stream path and token; a test client then plays Twilio's
part on the WebSocket. `services/capability_broker/tests/test_broker_voice.py` does this
against the real broker and gateway with mock models.

## Limitations

- One call at a time (the text-to-speech server generates one stream at a time).
- English only (VoXtream). R2T2's own low-latency streaming recognition is not used: each
  caller turn is transcribed as a whole after the pause.
- Turn detection is energy based: a noisy line can trigger or delay turns.
- A platform restart ends calls in progress; their transcripts are lost.
